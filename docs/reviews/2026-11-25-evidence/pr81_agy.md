### F3: `heterodyne_hybrid_streaming` excludes zero-weight rows from `info["n_data_points"]` while `info["ssr"]` still sums masked rows unweighted
- Must-fix: yes
- Location: xpcsjax/optimization/nlsq/strategies/heterodyne_hybrid_streaming.py:1034-1040,1064
- Scenario: Run `fit_with_stratified_hybrid_streaming_heterodyne` on data with zero-weight masked pixels (`weights = 0`, mapped to `sigma = inf` by `build_heterodyne_stratified_data`). Line 1034 now sets `info["n_data_points"]` to `n_contributing_points` (unmasked pixels only), while line 1040 computes `info["ssr"] = float(np.sum((y_data - pred) ** 2))` over ALL rows in `x_data`/`y_data` without applying `1 / sigma` or masking `sigma = inf` rows. Masked/artifact pixels remain in the numerator while being removed from the DOF denominator, inflating `chi_squared` and `reduced_chi_squared` arbitrarily.
- Evidence: Reproduced from `$WT` via `uv run --no-sync python -c '...'` on `n_phi=3, n_t=10` with 6 rows masked (`weights[:, 1:7, :] = 0.0`) and corrupted (`c2[:, 1:7, :] = 100.0`) under mocked `AdaptiveHybridStreamingOptimizer`: `info["n_data_points"] == 72`, `info["ssr"] == 1404048.73`, `reduced_chi2 == 24207.74`.
- Suggested fix: When `meta.get("sigma")` is present, compute `info["ssr"]` and `info["ssr_frozen_baseline"]` from `(y_data - pred) / sigma` (where `sigma = inf` contributes `0.0`, matching `heterodyne_stratified_ls.py:294,328,1237`) so numerator and denominator use the exact same weighted/masked observations.

### F4: `fit_two_component_via_engine` silently accepts all-zero (and non-positive) uniform weights under `loss="linear"`, solving unweighted
- Must-fix: yes
- Location: xpcsjax/optimization/nlsq/heterodyne_engine_route.py:457-477
- Scenario: Call `fit_two_component_via_engine(model, c2, phi, NLSQConfig(loss="linear"), weights=np.zeros_like(c2))` (or uniform negative/non-finite weights). Because `weights` is uniform (`np.allclose` is `True`) and `loss == "linear"`, both weight guards at lines 457 and 467 are bypassed. The engine drops `weights` and solves unweighted as if `weights=1.0`, then reports `chi_squared=0.0`, `reduced_chi_squared=0.0`, `quality_flag="good"`, `covariance_dof["n_valid"]=330`, and finite unweighted covariance/uncertainties despite zero weighted observations.
- Evidence: Reproduced from `$WT` via `uv run --no-sync python -c '...'` calling `fit_two_component_via_engine(model, c2, phi, NLSQConfig(loss="linear"), weights=np.zeros_like(c2))` on `n_phi=3, n_t=12`: returned normally with `chi2=0.0`, `reduced_chi2=0.0`, `cov_nan=False`, `n_valid=330`, `qflag='good'`.
- Suggested fix: In `heterodyne_engine_route.py:467-477`, also raise `NotImplementedError` whenever uniform `weights.flat[0]` is not strictly positive and finite (`not (np.isfinite(w0) and w0 > 0.0)`), routing all-zero/invalid weights to `fit_nlsq_multi_phi` where zero-weight DOF handling applies.
